\section{Experimental Methodology}
\label{sec:experimental-methodology}

\subsection{Environment, metrics, and statistics}

The retained experiments ran in the project's Docker/Windows Subsystem for Linux (WSL) environment using project container images, Python runners, Linux traffic control, ping, and iperf3. Exact host hardware utilization was not retained consistently, so hardware-level performance generalization is avoided. Every reported result is tied to a run directory or repository summary in the evidence inventory.

Version evidence is available only for the supplementary 50/100-Mbps bandwidth cohort. Its retained \path{runs/bandwidth-evidence-supplement/replication-attempt-02/environment.json} records Docker Server 29.1.3, Python 3.11.0rc1, and image identifier \path{sha256:98f003361bf86693b7dd562cf72629517de24793663898dd11898d112e092422}. The retained \path{Dockerfile.iperf} uses \path{ubuntu:22.04} as its base tag; this documents the build recipe rather than an independently captured host or container operating-system version. Exact Windows, WSL, Linux kernel/distribution, and iperf3 versions were not consistently retained and are not inferred.

The primary metrics are TCP throughput in Mbps, ping round-trip time (RTT) in milliseconds, end-to-end ping packet loss in percent, and controller reward. Repository-reported (RR) values preserve both the value and interval convention in the retained repository summary. Audit-computed (AC) statistics use complete retained per-run rows, the sample standard deviation, and a two-sided Student's $t$ 95\% confidence interval,
\[
  \bar{x} \pm t_{0.975,n-1}\frac{s}{\sqrt{n}}.
\]
No missing measurements are imputed. For the repeated delay and loss groups, a 200,000-permutation Kruskal--Wallis overall test uses midranks, tie correction, seed 20260821, and the finite-sample estimator $(b+1)/(B+1)$. Epsilon-squared, $(H-k+1)/(N-k)$, reports effect size. This rank-based test avoids relying on normality with $n=5$ and discrete loss values; no pairwise inference is made. The read-only derivative is retained at \path{derived/audit_computed_statistics/v1_4_inferential_analysis.json}. The RL summary's intervals use its repository summarizer's $1.96s/\sqrt{n}$ convention and remain descriptive RR values.

Appendix Tables~\ref{tab:experimental-matrix-rq1} and \ref{tab:experimental-matrix-rq23} fix each experiment's question, comparator, variables, cohort rule, analysis, and evidence. Historical BW20, Germany50, RL, AI, and Dashboard findings remain descriptive for the dependence or sample-size reasons stated there.

\subsection{Controlled impairment experiments}

The bandwidth evidence has deliberately unequal provenance. The direct-series 20-Mbps result is one retained historical client--router--server measurement using server-side token-bucket filtering (TBF), reported as $n=1$. The 50- and 100-Mbps results are later supplementary replications of the direct two-node, server-side TBF, five-second reverse-TCP iperf3 method. The supplement retains ten 50-Mbps attempts, including five earlier permission failures; the selected replicated cohort contains five valid observations. It retains sixteen 100-Mbps attempts across recorded batches; the selected cohort contains six attempts---one failed measurement plus its run-06 retry---and five valid observations. Excluded attempts and failures remain visible in \path{per-run-results.csv} and are not mixed into the selected-cohort statistics.

Latency used a 20-Mbps routed topology at configured one-way delays of 0, 10, 30, and 50 ms. Each condition has five valid runs and three ping packets per run. The dependent variable is measured RTT, not one-way latency. Packet-loss experiments configured one-way loss of 0, 1, 3, and 5\%, with five runs and 100 ping packets per run. Sent and received counts determine measured end-to-end loss. The dual-router benchmark used client--router1--router2--server, zero configured delay/loss, and five runs; it is analyzed separately from direct bandwidth evidence.

\subsection{Topology, AI, control, and interface experiments}

Three Germany50 path cases were fixed before execution: one, four, and nine backbone hops. Every link had 20 Mbps, 10-ms one-way delay, and 0\% loss, with three runs per case. Hop count therefore co-varies with cumulative configured delay; the cases cannot isolate a topology-only causal effect. Appendix Table~\ref{tab:appendix-germany50} gives the paths. A separate full-topology evaluation instantiated 50 nodes and 88 links. Selected routing installed 20 routes and produced nine measurements; full routing dry-run validated 4,224 entries without installing or exercising them as all-pairs traffic.

AI validation distinguishes the official OpenAI attempt from a separate OpenAI-compatible Qwen path. The official request produced HTTP 429 \texttt{insufficient\_quota}. The Qwen-compatible path produced a six-node scenario that passed schema, semantic, prompt-constraint, projection, dry-run, and controlled real-Docker validation.

The RL comparison contains 80 valid real-Docker episodes: 20 per policy for Q-learning, threshold heuristic, fixed A, and fixed B. It uses one seed and ordered sequential episodes; episodes are not independent randomized replications. RR intervals are retained descriptive summaries and do not establish inferential policy superiority. Two failed/retried checkpoints remain in provenance and are excluded from the valid rows. Appendix Table~\ref{tab:appendix-rl} reports all policies. The Dashboard is one documented direct UI-path smoke; absent raw validation logs determine its documented-only status.
